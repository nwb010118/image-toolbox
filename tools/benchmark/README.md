# 압축률 실측 스크립트

`run_benchmark.py`는 이미지 압축률을 형식(PNG/JPG/WebP)과 품질 설정별로 실제 측정해
`results.json`에 저장하는 재사용 가능한 스크립트입니다.

## 실행 방법

```bash
python3 tools/benchmark/run_benchmark.py
```

Python 3 + Pillow가 필요합니다. 실행하면 `samples/` 폴더에 테스트 이미지와 인코딩 결과물이
생성되고(버전 관리 대상 아님, `.gitignore` 처리됨), `results.json`이 갱신됩니다.

## 샘플 이미지

저작권 문제를 피하기 위해 외부 이미지를 쓰지 않고, 스크립트가 실행 시점에 직접 생성합니다.

- **photo_like**: 그라디언트 + 랜덤 노이즈로 만든 연속톤 이미지 (사진과 유사한 압축 특성)
- **graphic_like**: 단색 블록 + 직선으로 만든 이미지 (스크린샷·UI·로고와 유사한 압축 특성)

두 샘플 모두 1200×800px, 고정 시드(20260928)로 생성되어 재실행해도 같은 이미지가 나옵니다.

## 측정 항목

샘플별로 PNG(무손실) 1회 + JPG/WebP를 품질 100/90/80/60/40에서 각각 인코딩하여 기록합니다.

- `size_bytes`: 인코딩된 파일 크기
- `encode_time_ms`: 인코딩 소요 시간
- `reduction_vs_png_percent`: 원본 PNG 대비 용량 감소율 (그래픽형 이미지의 JPG는 원본보다
  커질 수 있어 음수로 나올 수 있습니다 — 이는 오류가 아니라 실제 측정 결과입니다)

## 중요: 이 사이트의 실제 도구와 다를 수 있음

이 스크립트는 **Python Pillow의 인코더**를 사용합니다. image-toolbox의 실제 압축 도구
(`index.html`)는 **브라우저의 Canvas API**(`canvas.toBlob`)로 인코딩합니다. 같은 품질
설정이라도 인코더 구현이 다르면 바이트 단위 결과는 달라질 수 있습니다.

이 스크립트의 결과는 "형식과 품질에 따라 압축률이 어떻게 달라지는가"라는 **경향성**을
보여주는 참고 자료이며, 브라우저에서 사용자가 실제로 얻는 파일 크기를 그대로
재현한다고 보장하지 않습니다. 사이트 콘텐츠에 이 결과를 인용할 때는 이 차이를 함께
밝혀야 합니다.

## 재실행이 필요한 경우

이미지 샘플 생성 로직이나 측정 조건(해상도, 품질 목록)을 바꾸면 `results.json`이
이전 값과 달라지므로, 사이트 콘텐츠에 인용된 수치도 함께 갱신해야 합니다.
