# 업스케일링 배율/해상도 선택 기능 Design

**Goal:** 기존에 2배 고정이던 `upscale.html`의 업스케일링을 배율(2배/4배)과 목표 해상도(1440p/4K) 중 하나를 선택할 수 있도록 확장한다. AI 모델 자체는 2배율 하나뿐이므로, 2배 패스를 체이닝하고 필요시 캔버스로 정밀 축소해 목표 값을 정확히 맞춘다.

**Architecture:** 기존 구조를 그대로 따른다. 순수 계산 로직(패스 수/최종 리사이즈 여부 계산, 도달 가능 여부 판정, 파일명 생성)은 `js/upscaleTools.js`에 추가해 Node로 유닛테스트하고, DOM 이벤트·UpscalerJS 호출·진행률 표시는 `js/upscaleApp.js`에서 그 함수들을 소비한다. `upscale.html`에는 배율/해상도를 고르는 라디오 버튼 그룹을 추가한다. 새 라이브러리나 CDN 스크립트는 추가하지 않는다 — 기존 `ESRGANSlim2x` 2배 모델을 여러 번 호출하는 것으로 해결한다.

## 핵심 알고리즘

**모드 4종:** `2x`, `4x`, `1440p`(긴 변 2560px), `4K`(긴 변 3840px). 해상도 프리셋은 원본 가로/세로 비율을 유지한 채 **긴 변** 기준으로 목표 크기를 계산한다 (사진마다 가로/세로가 다르므로).

**패스 수 계산 (`getUpscalePlan(mode, width, height)`):**
- `2x` → AI 패스 1회, 최종 리사이즈 없음 (원본의 정확히 2배가 그대로 결과)
- `4x` → AI 패스 2회 체이닝(1차 결과를 2차 입력으로), 최종 리사이즈 없음
- `1440p`/`4K` → 목표 긴 변 값을 원본 긴 변 값으로 나눠 필요 배율 계산
  - 필요 배율 ≤ 2 → AI 패스 1회
  - 필요 배율 ≤ 4 → AI 패스 2회
  - 필요 배율 > 4 → **도달 불가** (`reachable: false` 반환, 호출 측에서 UI 비활성화에 사용)
  - 도달 가능한 경우, AI 패스 후 캔버스로 정확한 목표 긴 변 픽셀 수까지 축소하는 최종 리사이즈 단계를 거친다 (짧은 변은 같은 비율로 축소).

**도달 가능 여부 판정 (`isReachable(mode, width, height)`):** 긴 변 × 4 ≥ 목표 해상도인지로 판정. `1440p`는 긴 변 640px 미만, `4K`는 긴 변 960px 미만인 원본에서 비활성화된다. 입력 크기 제한(1000px)이 기존과 동일하게 유지되므로, 결과물 크기는 항상 최대 4000×4000px로 예측 가능하다 (AI 패스가 최대 2회로 고정).

**진행률 표시:** 패스가 여러 개일 때 `(완료된 패스 수 + 현재 패스 진행률) / 전체 패스 수`로 환산해 하나의 퍼센트로 이어서 보여준다. 최종 리사이즈 단계는 동기 캔버스 연산이라 순간적으로 끝나므로 별도 진행률 구간을 두지 않는다.

## UI 변경 (`upscale.html`, `js/upscaleApp.js`)

- 이미지 선택 후 기존 "2배로 확대" 버튼 자리를 라디오 버튼 그룹(`2배`, `4배`, `1440p`, `4K`, 기본값 `2배`) + 실행 버튼 "확대하기"로 교체. 기존 `.controls`/`.checkbox-label` 스타일 패턴을 재사용한다.
- 파일 업로드 직후 `isReachable`로 각 라디오를 평가해, 도달 불가능한 옵션은 `disabled` 처리하고 옆에 회색 안내 문구를 붙인다 (예: "이 이미지로는 도달할 수 없어요 (긴 변 최소 960px 필요)"). 이전에 선택돼 있던 모드가 새 이미지에서 비활성화되면 기본값(`2배`)으로 되돌린다.
- 결과 미리보기 제목(`결과 (2배)` → `결과 (4배)`/`결과 (1440p)`/`결과 (4K)`)과 다운로드 파일명 접미사(`-2x.png`/`-4x.png`/`-1440p.png`/`-4K.png`)가 선택한 모드에 따라 동적으로 바뀐다.
- 여러 패스를 도는 동안 `upscaler.upscale()`을 순차적으로 호출한다 (1차 결과 데이터 URL을 2차 입력으로 그대로 사용). 싱글턴 `upscaler` 인스턴스는 기존과 동일하게 재사용한다.

## 파일 구조 변경

- `js/upscaleTools.js` (수정) — `getUpscalePlan`, `isReachable`, 모드별 파일명 생성 함수 추가. 기존 `getUpscaledFilename(name)`은 `getUpscaledFilename(name, mode)`로 시그니처 변경.
- `tests/upscaleTools.test.js` (수정) — 위 함수들에 대한 유닛테스트 추가 (경계값: 긴 변 정확히 640/960px, 999px, 1000px 등).
- `upscale.html` (수정) — 라디오 버튼 그룹 마크업 추가, FAQ "몇 배까지 확대할 수 있나요?" 답변 및 title/description 메타 텍스트 갱신.
- `js/upscaleApp.js` (수정) — 모드 선택 읽기, 패스 체이닝, 최종 리사이즈, 도달 가능 여부에 따른 라디오 활성화/비활성화, 결과 제목·파일명 동적 갱신.
- `css/style.css` (필요시 수정) — 라디오 그룹에 기존 `.controls`/`.checkbox-label` 패턴 재사용, 비활성 옵션 안내 문구용 스타일 소폭 추가.

## 범위 밖

- 6배, 8배 등 2의 거듭제곱이 아니거나 4배를 초과하는 배율 — 사용자가 명시적으로 제외하기로 결정함
- 원본이 목표 해상도에 못 미칠 때 일반(보간) 확대로 마저 채우는 방식 — 대신 옵션을 비활성화하는 쪽을 선택함
- 여러 장 일괄 처리, 입력 크기 제한(1000px) 자체의 변경

## 검증

- `tests/upscaleTools.test.js`에 `getUpscalePlan`/`isReachable`/파일명 함수 경계값 유닛테스트
- 브라우저에서: (1) 작은 이미지(예: 500×500)로 1440p/4K가 비활성화되는지, (2) 1000×1000 이미지로 4x·4K가 정상 동작하고 정확한 픽셀 크기가 나오는지, (3) 2x/4x 결과가 정확히 원본의 2배/4배 크기인지, (4) 진행률 표시가 패스 전환 시 끊기지 않고 이어지는지 수동 확인
- 다운로드 파일명이 모드별로 올바른 접미사를 갖는지 확인
