# PDF 변환 기능 설계 문서

- 작성일: 2026-08-11
- 상태: 승인됨 (구현 계획 단계로 진행)
- 상위 문서: [2026-08-10-image-toolbox-design.md](2026-08-10-image-toolbox-design.md)

## 배경 및 목표

기존 이미지 압축·리사이즈·포맷 변환 도구(`index.html`)에 이어, PDF 관련 변환 기능을 별도 도구로 추가한다. "이미지 압축"과 "PDF 변환"은 검색 의도가 다른 키워드이므로, SEO 유입을 위해 별도 페이지로 분리한다.

## 범위

두 방향을 모두 지원한다:

1. **이미지 → PDF**: 여러 장의 이미지(JPG/PNG/WebP)를 업로드 순서대로 한 개의 PDF 파일로 합친다.
2. **PDF → 이미지**: PDF 파일의 각 페이지를 PNG 이미지로 추출한다.

## 목표가 아닌 것 (Out of Scope)

- 워드/엑셀/파워포인트 변환 — 별도 검토 대상, 이번 범위에서 제외
- 이미지 → PDF에서 페이지 순서 드래그 재정렬 — 업로드(선택)한 순서를 그대로 사용
- PDF → 이미지에서 여러 페이지를 ZIP으로 묶어 한 번에 다운로드 — 페이지별 개별 다운로드 버튼만 제공
- PDF → 이미지 출력 포맷 선택 — PNG로 고정
- PDF 페이지 자체의 편집, 병합/분할, 텍스트 추출, 워터마크 등 그 외 PDF 조작 기능
- 서버 API를 통한 변환 — 파일이 서버로 전송되지 않는다는 기존 원칙을 그대로 유지

## 기술 스택 / 라이브러리

기존 프로젝트는 빌드 도구·외부 라이브러리 없이 순정 Web API(Canvas, File API)만 사용해왔다. 그러나 브라우저에는 PDF를 직접 읽거나 만드는 네이티브 API가 없으므로, 이 기능에 한해 예외적으로 외부 라이브러리를 CDN으로 로드한다 (사용자 승인됨). 서버로 파일이 전송되지 않는다는 원칙은 그대로 유지된다 — 라이브러리는 브라우저 안에서 클라이언트 사이드로만 동작한다.

- **pdf.js** (Mozilla 공식) — PDF 페이지를 canvas에 렌더링 (PDF → 이미지)
- **jsPDF** — 이미지를 PDF 페이지로 합성 (이미지 → PDF)
- 두 라이브러리 모두 특정 버전을 CDN URL에 고정한다 ("latest" 사용 금지 — 무인 운영 프로젝트이므로 예고 없는 breaking change를 피한다).
- 두 라이브러리는 `pdf.html`에서만 로드한다. `index.html`(이미지 압축 도구)은 전혀 영향받지 않는다 — 이미지 도구만 쓰는 방문자가 불필요하게 무거운 PDF 라이브러리를 받지 않도록 하기 위함.

## 파일 구조

- `pdf.html` (신규) — PDF 변환 페이지. `index.html`과 같은 헤더/스타일 톤을 유지하고, 상단에 서로를 연결하는 링크를 둔다.
- `css/style.css` (수정) — PDF 페이지 전용 스타일(다중 파일 목록, 페이지별 썸네일·다운로드 버튼, 진행 표시) 추가
- `js/pdfTools.js` (신규) — 순수 함수: 파일명 생성, PDF/이미지 파일 유효성 검사, 개수 제한 검사. Node로 유닛테스트.
- `js/pdfApp.js` (신규) — DOM 이벤트 와이어링, pdf.js/jsPDF 호출, canvas 렌더링 오케스트레이션
- `tests/pdfTools.test.js` (신규) — `js/pdfTools.js`에 대한 Node 기반 유닛테스트 (기존 `tests/imageTools.test.js`와 동일한 패턴)
- `index.html` (수정) — 상단에 "PDF 변환 도구" 링크 추가

`pdf.html`은 `js/imageTools.js`도 함께 로드하여 `formatBytes`, `isSupportedImageType` 등 기존 순수 함수를 재사용한다 (중복 구현하지 않음).

## 핵심 기능 및 데이터 흐름

### 1. 이미지 → PDF

1. 다중 파일 선택 input + 드래그드롭으로 여러 이미지를 한 번에 선택한다.
2. 각 파일에 대해 검증: `isSupportedImageType`(JPG/PNG/WebP), 파일당 20MB 이하(기존 `MAX_FILE_SIZE` 재사용), 전체 최대 50장(구현 안전장치 — 브라우저 메모리 보호 목적, 스펙에 명시되지 않음). 하나라도 유효하지 않으면 전체 요청을 반려하고 어떤 파일이 문제인지 한국어 에러 메시지로 안내한다 (부분 처리 없음).
3. 선택(업로드) 순서대로 각 이미지를 `Image` 객체로 로드해 `naturalWidth`/`naturalHeight`를 얻는다.
4. jsPDF로 문서를 생성한다. 첫 이미지의 크기로 `unit: 'px'`, `format: [width, height]`를 지정해 문서를 초기화하고, 이후 이미지마다 `addPage([width, height], orientation)` 후 `addImage`로 이미지를 여백 없이 페이지에 꽉 채운다 (이미지 크기 그대로, 리사이즈/레터박스 없음).
5. 모든 페이지 추가 후 `doc.output('blob')`으로 blob을 만들고, 기존 이미지 도구와 동일한 방식(objectURL + `<a download>`)으로 `images.pdf` 다운로드 링크를 제공한다.

### 2. PDF → 이미지

1. 단일 PDF 파일 선택. `file.type === 'application/pdf'` 확인, 일부 브라우저가 타입을 비워 보내는 경우를 대비해 파일명이 `.pdf`로 끝나는지 보조 검사도 함께 한다.
2. pdf.js(`pdfjsLib.getDocument`)로 문서를 열고 `numPages`를 확인한다. 300페이지 초과 시 구현 안전장치로 에러를 표시하고 중단한다 (스펙에 명시되지 않음, 브라우저 렌더링 부하 방지 목적).
3. 페이지 1부터 순서대로 off-screen canvas에 렌더링(`scale: 2`)하고 `canvas.toBlob(..., 'image/png')`으로 PNG blob을 만든다. 각 페이지 처리 후 곧바로 썸네일과 "페이지 N 다운로드" 버튼을 화면에 추가한다 (전체 완료를 기다리지 않고 페이지별로 점진적으로 표시).
4. 전체 페이지 처리 중에는 "처리 중... (N/전체)" 진행 문구를 표시한다.
5. 손상되었거나 읽을 수 없는 PDF는 `getDocument` promise가 reject되며, 한국어 에러 메시지("PDF 파일을 읽을 수 없습니다")를 표시한다.

## 에러 처리

- 지원하지 않는 파일 형식/개수/크기 초과 시 한국어 안내 메시지 (기존 이미지 도구와 동일한 톤)
- CDN에서 pdf.js/jsPDF 로드에 실패한 경우(오프라인 등), 실제 사용 시점에 `typeof pdfjsLib`/`typeof jspdf` 존재 여부를 확인해 "PDF 처리 기능을 불러오지 못했습니다. 인터넷 연결을 확인해주세요." 같은 메시지로 안내한다.
- 모든 처리는 브라우저 내부에서만 이루어지며 파일은 서버로 전송되지 않는다 — 기존 원칙 유지.

## 네비게이션

- `index.html` 상단에 "PDF 변환 도구 →" 링크를 추가해 `pdf.html`로 연결한다.
- `pdf.html` 상단에 "← 이미지 압축 도구" 링크를 추가해 `index.html`로 연결한다.
- 별도 페이지로 분리한 이유: (1) "이미지 압축"과 "PDF 변환"은 검색 의도가 다른 키워드라 페이지를 나눠야 SEO에 유리하다. (2) pdf.js/jsPDF는 용량이 커서, 이미지 도구만 쓰려는 방문자가 불필요하게 이 라이브러리를 받지 않도록 페이지를 분리한다.

## 테스트 방침

- `js/pdfTools.js`의 순수 함수(파일명 생성, 유효성 검사, 개수 제한)는 `tests/pdfTools.test.js`에서 Node 기반으로 유닛테스트한다 (기존 `tests/imageTools.test.js`와 동일한 패턴, 외부 의존성 없이 실행 가능).
- canvas 렌더링, pdf.js/jsPDF 연동 등 브라우저 전용 로직은 자동화 테스트 대상이 아니며, 실제 브라우저에서의 수동 검증에 무게를 둔다 (기존 이미지 도구와 동일한 테스트 방침).

## 성공 기준

- `index.html`에 변경이 없거나(라이브러리 미로드) 최소한의 링크 추가만 있어, 기존 이미지 도구의 로딩 속도·동작에 영향이 없다.
- 이미지 여러 장을 업로드해 순서대로 페이지가 구성된 PDF를 다운로드할 수 있다.
- 여러 페이지짜리 PDF를 업로드해 페이지별로 PNG를 개별 다운로드할 수 있다.
- 지원하지 않는 파일, 개수/용량 초과, 손상된 PDF 등 주요 실패 상황에서 한국어 에러 메시지가 표시된다.
