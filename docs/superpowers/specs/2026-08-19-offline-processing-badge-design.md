# 처리 버튼 옆 "오프라인 처리" 배지 설계 문서

- 작성일: 2026-08-19
- 상태: 승인됨 (구현 계획 단계로 진행)

## 배경 및 목표

스레드에 공개한 image-toolbox 사이트에 대한 사용자 피드백(verticaltech.kr) 중, "파일이 서버로 전송되지 않는다는 게 이 도구의 가장 큰 장점인데, 그게 화면에 안 보이면 사람들이 못 믿는다. 변환 버튼을 누르고 처리되는 순간에도 다시 한번 보여주면 전환율이 달라진다"는 지적이 있었다.

현재 각 페이지 상단에는 "사진이 서버로 전송되지 않고, 이 브라우저 안에서만 처리됩니다"라는 부제(subtitle) 문구가 이미 있다. 하지만 이는 페이지 진입 시 한 번 보이는 정적 문구일 뿐, 사용자가 실제로 "변환하기"/"적용하기" 같은 액션 버튼을 누르는 순간(신뢰가 가장 필요한 시점)에는 눈에 다시 들어오지 않는다. 이 설계는 액션 버튼 근처에 같은 메시지를 짧게 재노출해, 행동하는 바로 그 지점에서 신뢰를 재확인시키는 것이 목표다.

## 범위

- 사이트의 모든 처리 액션 지점에 "서버 전송 없음" 배지(아이콘 + 짧은 텍스트)를 추가한다:
  - `index.html` — 이미지 압축 "적용하기" 버튼 아래
  - `upscale.html` — "확대하기" 버튼 아래
  - `pdf.html` — "PDF로 변환"(이미지→PDF) 버튼 아래
  - `pdf.html` — "변환하기"(PDF→문서변환) 버튼 아래
  - `pdf.html` — PDF→이미지는 별도 액션 버튼이 없고 파일 선택 즉시 처리되는 구조이므로, 해당 업로드 영역 바로 아래에 배치한다
- 배지는 **정적**이다 — 배지 자체는 JS 상태에 따라 별도로 토글되지 않는다. `index.html`/`upscale.html`, 그리고 `pdf.html`의 PDF→문서변환 섹션에서는 배지가 파일 선택 후에만 열리는 `.controls` 영역 안에 있어 페이지 로드 직후에는 보이지 않고 액션 버튼이 나타날 때 함께 나타난다. `pdf.html`의 이미지→PDF, PDF→이미지 두 섹션에서는 `.controls` 밖에 있어 페이지 로드 시부터 보인다. 두 경우 모두 처리 시작~진행~완료 전 과정에서 계속 보이므로, "처리되는 순간에도 보인다"는 목표를 만족하면서 JS 상태 로직을 전혀 건드리지 않는다.
- 아이콘은 기존 업로드 아이콘(`upload-icon`)과 동일한 스타일(24x24 viewBox, `stroke` 기반 선형 아이콘, `stroke-width: 1.5`, round cap/join)로 만든 자물쇠 모양 아이콘을 새로 그린다. 이모지는 쓰지 않는다(기존 사이트에 이모지 사용 사례 없음).
- 문구는 "서버 전송 없음 · 브라우저에서만 처리"로 통일한다(기존 부제 문구와 표현을 다르게 해 단순 반복처럼 보이지 않게 하되, 같은 사실을 전달).

## 목표가 아닌 것 (Out of Scope)

- JS로 처리 상태(진행 중/완료)에 따라 배지를 동적으로 보이거나 숨기는 것 — 정적 배치로 충분하다고 판단해 제외.
- 페이지 URL 구조 변경 — 피드백의 다른 제안(도구별 URL 분리)은 이미 사이트에 구현되어 있어 이번 범위에서 다루지 않는다.
- Search Console 사이트맵/URL 색인 요청 — 별도 작업으로 처리(코드 변경이 아님).

## 기술 방식

- `css/style.css`에 새 클래스 2개 추가: `.offline-badge`(flex, 아이콘+텍스트 정렬, `font-size: 12px`, `color: var(--color-text-secondary)`), `.offline-badge-icon`(`width/height: 14px`, `color: currentColor`로 배지 텍스트 색을 그대로 물려받음 — 기존 accent 색 아이콘들과 달리 튀지 않는 조용한 신뢰 신호로 의도).
- 5곳의 HTML에 동일한 배지 마크업(아이콘 SVG + 문구)을 각각 삽입한다. 컴포넌트화/템플릿 시스템이 없는 순수 정적 사이트이므로 마크업 반복은 기존 업로드 아이콘 반복과 동일한 패턴이다.
- JS 파일은 전혀 수정하지 않는다.

## 에러 처리

해당 없음 — 순수 정적 표시 요소로, 실패할 수 있는 로직이 없다.

## 테스트 방침

- 순수 마크업/스타일 변경이라 자동화 테스트 대상이 아니다.
- 수동 확인: 5개 페이지 각각에서 배지가 해당 버튼/업로드 영역 아래에 올바르게 보이는지, 모바일 폭에서 줄바꿈이 깨지지 않는지 확인한다.

## 성공 기준

- 5개 처리 지점(이미지 압축, 업스케일링, 이미지→PDF, PDF→이미지, PDF→문서변환) 모두에서 액션 버튼/업로드 영역 바로 아래에 "서버 전송 없음 · 브라우저에서만 처리" 배지가 보인다.
- 기존 기능(각 도구의 실제 처리 로직)에 회귀가 없다 — JS를 건드리지 않았으므로 자동으로 만족된다.
