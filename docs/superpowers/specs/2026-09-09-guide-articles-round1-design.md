# 정보성 가이드 글 1차 라운드(5개) 설계 문서

- 작성일: 2026-09-09
- 상태: 승인됨 (구현 계획 단계로 진행)

## 배경 및 목표

AdSense 반려 대응 5단계 계획의 4단계. 진단 문서가 "정보성 가이드 글 10~20개 축적"을 제안했지만, 한 번에 다 만들면 품질 관리가 어렵고 이 프로젝트가 지금까지 지켜온 톤(실측·정직한 한계 고지·과장 없는 설명)을 유지하기 힘들어진다. 그래서 5개씩 배치로 나눠 진행하기로 했고, 이 문서는 1차 배치(5개)를 다룬다.

## 범위

저장소 루트에 신규 정적 페이지 5개를 추가한다. 새 변환 로직은 없다 — 각 글은 정보를 제공하고 필요한 지점에서 기존 도구(`index.html`/`pdf.html`/`upscale.html`)로 자연스럽게 연결한다.

1. `kakao-photo-quality.html` — 카카오톡 사진 전송 시 화질 저하
2. `email-attachment-size.html` — 이메일 첨부파일 용량 제한
3. `image-format-comparison.html` — PNG/JPG/WebP 심층 비교
4. `photo-id-resize.html` — 여권사진·증명사진 규격 리사이즈
5. `ai-upscaling-limits.html` — AI 업스케일링의 한계

## 목표가 아닌 것 (Out of Scope)

- 2차 이후 배치(나머지 5~15개) — 이번 라운드 효과를 본 뒤 진행 여부 결정.
- 5단계(사이트맵 재제출 → 애드센스 재신청) — 4단계 전체(여러 배치)가 끝난 뒤 한 번에.
- 실제 카카오톡/이메일 서비스 스크린샷 — 서드파티 서비스의 UI를 캡처해서 싣는 것은 저작권·변경 리스크가 있어 텍스트 설명으로 대체.

## 공통 콘텐츠 구조

기존 `about.html`/`benchmark.html`과 동일하게 `container`/`subtitle`/`tool-nav`/`info-section`/`btn`/`site-footer` 클래스를 재사용한다. 각 글은 아래 순서를 따른다:

1. **H1 + 도입** — 왜 이게 문제/궁금증이 되는지 구체적 상황 제시
2. **본문 설명** — 실제 사실에 근거한 설명(원인, 규격, 비교 등). 검증되지 않은 추측은 쓰지 않는다.
3. **도구 연결** — 설명 흐름상 자연스러운 지점에 이 사이트 도구로의 CTA 링크
4. **자주 묻는 질문** — 3~4개, 본문과 겹치지 않는 구체적 질문
5. **관련 페이지 링크**

## 글별 핵심 내용 (사실 확인 완료)

### 1. `kakao-photo-quality.html`
카카오톡은 대화방에서 사진을 전송할 때 자동으로 압축해서 보낸다(원본 그대로 전송 아님). "원본 크기로 보내기" 옵션을 켜면 압축 없이 보낼 수 있지만 대신 전송 속도가 느려지고 상대방 데이터도 더 든다. 반대로 용량 자체를 줄여서 빠르게 여러 장 보내고 싶다면 미리 압축하는 게 유리하다는 흐름으로 `index.html`을 자연스럽게 연결한다.

### 2. `email-attachment-size.html`
실측(웹 검색으로 확인한) 첨부 용량 제한:
- **Gmail**: 기본 25MB. 초과 시 자동으로 Google Drive 링크로 전환됨.
- **네이버메일**: 기본 10MB, 대용량 첨부 기능으로 최대 2GB(파일당, 최대 10개, 총 20GB)까지 가능.
- **다음메일**: 기본 25MB, 대용량 첨부 기능으로 최대 4GB까지 가능.

기본 용량 제한에 걸리는 경우(대용량 첨부 기능을 안 쓰거나 못 쓰는 상황) 사진 여러 장을 압축하거나, 여러 장을 하나의 PDF로 합쳐서 보내는 방법을 `index.html`/`photos-to-pdf.html`로 연결해 제시한다.

### 3. `image-format-comparison.html`
이미 `index.html`에 짧은 형식 비교 섹션이 있지만, 이 글은 그보다 깊게: 각 형식의 압축 방식(무손실/손실) 차이, 투명도 지원 여부, 브라우저/프로그램 호환성, 그리고 **`benchmark.html`의 실측 데이터를 직접 인용**(값을 다시 측정하지 않고 링크 + 핵심 수치만 요약)해서 "이론이 아니라 실측으로 봐도 이렇다"는 근거를 제공한다. 데이터를 중복 생성하지 않고 benchmark.html을 근거로 삼는 것이 핵심.

### 4. `photo-id-resize.html`
실측(웹 검색으로 확인한) 규격:
- 여권·주민등록증·운전면허증 사진: 인화 기준 **35mm × 45mm** 동일 규격.
- 온라인 여권 신청용 디지털 사진: **413 × 531 픽셀** 권장.
- 해상도: **300DPI 이상** 권장.
- 얼굴(정수리~턱) 길이: 3.2~3.6cm.
- 배경은 흰색, 안경 착용 금지 등 촬영 조건도 간단히 언급.

`index.html`의 가로/세로 픽셀 직접 입력 기능으로 413×531px에 맞추는 방법을 안내하며 연결한다.

### 5. `ai-upscaling-limits.html`
`upscale.html`에 이미 있는 "AI 업스케일링은 어떻게 동작하나요" 섹션의 기술적 사실(ESRGAN 계열 경량 모델, 2배씩 확대, 최대 4배)을 근거로 삼아, **AI 업스케일링이 실제로 도와줄 수 있는 것**(선명도 개선, 확대 시 디테일 보강)과 **도와줄 수 없는 것**(원본에 없는 정보를 만들어내는 게 아니므로 초점이 심하게 나간 사진이나 완전히 뭉개진 저해상도 원본은 한계가 있음, 인물 얼굴을 다른 사람처럼 "복원"하는 게 아님)을 과장 없이 정직하게 설명한다. 이 사이트의 다른 콘텐츠(About 페이지, upscale.html)와 톤을 맞춘다 — 마케팅 문구가 아니라 실제 한계 고지.

## SEO 메타데이터 & 구조화 데이터

기존 페이지들과 동일한 패턴(`title`/`meta description`/`canonical`/`og:type`=article/`og:title`/`og:description`/`og:url`/`og:locale`). 구조화 데이터는 `Article` 타입(guide.html/about.html/benchmark.html과 동일 패턴).

## 내부 링크 연결

- `guide.html`에 5개 글로 가는 링크를 문맥에 맞는 섹션에 추가한다(예: 1번 섹션에 카카오톡 글, 3번 섹션에 여권사진 글 등 — 태스크 단계에서 정확한 위치 결정).
- `image-format-comparison.html` ↔ `benchmark.html` 상호 링크.
- `ai-upscaling-limits.html` ↔ `upscale.html` 상호 링크.
- `sitemap.xml`에 5개 URL 추가.
- 5개 글 footer에도 About/문의/개인정보처리방침 링크를 넣는다(기존 모든 콘텐츠 페이지와 동일한 footer 패턴 — `benchmark.html`은 예외적으로 footer에 넣지 않기로 했었지만, 이번 5개는 정보성 "가이드 글" 카테고리라 `guide.html`과 같은 성격으로 보고 표준 footer를 적용한다).

- `image-format-comparison.html`이 `benchmark.html`의 실측 데이터를 중복 생성 없이 인용한다.
- `guide.html`, `sitemap.xml`에 5개 페이지가 반영되어 있다.
- 기존 페이지/기능에 회귀가 없다.
