# 이미지 도구함 — 무자본 마이크로 SaaS 설계 문서

- 작성일: 2026-08-10
- 상태: 승인됨 (구현 계획 단계로 진행)

## 배경 및 목표

사용자는 코딩 경험이 전혀 없고, 완전 무자본(초기 투자 0원)으로 자동화된 수익 구조를 만들고자 한다. 유료 API는 사용하지 않으며(무료 API는 허용), 유지보수에는 주당 몇 시간 정도만 투자할 수 있다. 특정 관심 분야는 없어 방향을 추천받아 결정했다.

브레인스토밍을 통해 세 가지 방향(A. 미니 웹 도구, B. 콘텐츠 자동화 블로그, C. 핫딜 큐레이션 텔레그램 채널)을 비교했고, 완전 무료로 리스크 없이 장기 운영 가능하다는 이유로 **A. 미니 웹 도구(마이크로 SaaS)**를 선택했다. 주제는 검색량이 크고 법적/정확성 리스크가 없으며 순수 브라우저 처리가 가능한 **이미지/파일 도구**로 정했다.

## 목표가 아닌 것 (Out of Scope)

- 회원가입/로그인, 사용자 계정, 파일 서버 저장 — 서버 비용 발생과 개인정보 이슈를 피하기 위해 처음부터 배제
- 유료 API 연동 (예: AI 기반 배경 제거, 초해상도 등)
- 초기 단계의 결제 시스템/프리미엄 기능 — 수익이 생긴 이후 별도 단계로 진행

## 핵심 기능 (MVP)

순수 브라우저 처리(Canvas API)로 서버 없이 동작하는 이미지 도구 사이트:

1. 이미지 압축 (품질 조절 슬라이더)
2. 이미지 리사이즈 (크기 변경)
3. 포맷 변환 (JPG ↔ PNG ↔ WebP)
4. 여러 장 한번에 처리 (배치)

모든 처리는 클라이언트(브라우저) 내부에서만 이루어지며 파일이 서버로 전송되지 않는다. 이는 서버 비용을 0원으로 유지하는 동시에 "사진이 서버에 업로드되지 않는다"는 개인정보 보호 포인트로 마케팅에도 활용한다.

## 기술 스택

- **순수 HTML/CSS/JavaScript, 빌드 도구 없음.** React 등 프레임워크를 쓰지 않는다.
  - 이유: 사용자가 코드를 직접 작성하지 못하므로, 향후 수정 요청 시 빌드 과정 없이 파일을 바로 고쳐서 배포할 수 있어야 유지보수 마찰이 최소화된다.
- 외부 라이브러리는 CDN 없이 최대한 순정 Web API(Canvas, File API)로 구현한다. 외부 스크립트 의존을 늘리면 무료 API 제약과 별개로 유지보수 부담이 커진다.

## 배포

- **GitHub Pages**(무료)에 정적 사이트로 배포한다.
- 초기 주소는 `사용자명.github.io/이미지도구` 형태의 무료 서브패스로 시작한다.
- 수익이 발생하면 커스텀 도메인(연 1~2만원 수준)으로 전환한다. 전환은 GitHub Pages 설정만으로 가능하다.

## 수익화 전략 (단계적)

1. **1단계 (트래픽 없음~초기)**: 광고 없이 도구와 SEO 콘텐츠만으로 검색 유입을 쌓는다.
2. **2단계 (방문자 발생 시)**: 구글 애드센스 신청. 승인 심사에는 어느 정도의 콘텐츠와 트래픽이 필요하므로 1단계 이후 진행한다.
3. **병행**: 애드센스와 별개로 **카카오 애드핏**을 함께 붙인다 (심사가 상대적으로 수월하고 국내 트래픽에 적합, 애드센스와 병행 가능).
4. **제휴 배너**: 이미지/사진과 관련지을 수 있는 **쿠팡파트너스** 등 제휴 링크를 콘텐츠 문맥에 맞는 위치에 배치한다 (예: 카메라, 클라우드 저장 관련 상품).
5. **나중 단계 (수익 발생 후)**: 대용량 배치 처리, 워터마크 제거 등 고급 기능을 유료화하는 프리미엄 모델을 검토한다. 결제 시스템 연동이 필요하므로 초기 범위에서는 제외한다.

## SEO 전략

"이미지 압축", "사진 용량 줄이기", "jpg png 변환", "webp 변환기" 등 실제 검색 수요가 있는 한국어 키워드를 겨냥한다. 도구 페이지 자체에 사용법 설명, 자주 묻는 질문 등 한국어 콘텐츠를 함께 배치해 검색엔진이 페이지 맥락을 이해하도록 돕는다.

## 에러 처리

- 지원하지 않는 파일 형식 업로드 시 명확한 한국어 안내 메시지 표시
- 브라우저가 특정 포맷(예: WebP 인코딩)을 지원하지 않을 경우 안내 후 대체 옵션 제공
- 처리 중 브라우저 메모리 한계를 넘는 대용량 파일에 대한 경고 표시

## 테스트 방침

자동화 테스트보다 실제 브라우저에서의 수동 검증에 무게를 둔다 (프론트엔드 단일 정적 사이트이므로):
- 주요 브라우저(Chrome, Edge, 모바일 Safari/Chrome)에서 각 기능(압축/리사이즈/변환/배치) 동작 확인
- 다양한 원본 포맷·용량의 샘플 이미지로 결과물 검증
- 반응형 레이아웃(모바일 화면) 확인

## 로드맵

1. **0단계**: 이미지 압축 기능만 있는 최소 버전 제작 → GitHub Pages 배포
2. **1단계**: 리사이즈, 포맷 변환, 배치 처리 기능 추가
3. **2단계**: SEO용 한국어 설명 콘텐츠 보강, 검색 유입 확인
4. **3단계**: 방문자 발생 시 애드센스+애드핏 신청 및 광고 삽입, 쿠팡파트너스 배너 추가
5. **4단계 (선택)**: 수익 발생 시 커스텀 도메인 구매, 프리미엄 유료 기능 검토

## 성공 기준 및 현실적 기대치

이 프로젝트는 "완전 무자본으로 시작해 꾸준히 운영하면 서서히 쌓이는" 구조를 목표로 한다. 대박성 수익이 아니라 장기적 SEO 트래픽 축적이 선행되어야 광고 수익으로 이어지며, 확실한 수익을 보장하지 않는다는 점을 사용자와 명시적으로 합의했다. 1차 성공 기준은 "0단계~2단계까지 완성하여 실제 배포된 도구가 검색엔진에 노출되기 시작하는 것"으로 정의한다.
