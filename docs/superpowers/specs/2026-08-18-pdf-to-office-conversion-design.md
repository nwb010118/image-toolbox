# PDF → 문서(PPT/Word/Excel) 변환 기능 설계 문서

- 작성일: 2026-08-18
- 상태: 승인됨 (구현 계획 단계로 진행)
- 상위 문서: [2026-08-11-pdf-conversion-design.md](2026-08-11-pdf-conversion-design.md) — 해당 문서에서 "워드/엑셀/파워포인트 변환"은 범위 외로 명시적으로 제외됐었으며, 이 문서가 그 후속 작업이다.

## 배경 및 목표

기존 `pdf.html`은 이미지↔PDF 변환만 지원한다. 이번 작업은 PDF를 업로드해 PowerPoint(.pptx), Word(.docx), Excel(.xlsx) 중 원하는 형식으로 변환하는 기능을 같은 페이지에 추가한다.

세 형식은 구현 난이도와 결과물 신뢰도가 서로 다르다:
- **PPT**: 페이지를 이미지로 그대로 슬라이드에 삽입 — 시각적 충실도가 높고 구현 위험이 낮다.
- **Word**: 텍스트를 추출해 문단으로 재구성 — 단순한 문서는 무난하지만 복잡한 레이아웃(다단, 표, 이미지 혼합)은 원문과 다르게 보일 수 있다.
- **Excel**: 표 구조 인식이 필요한데, 클라이언트 사이드에서 신뢰도 높게 하기 가장 어렵다.

이 차이를 사용자에게 명시적으로 확인받았고, 아래 범위는 그 결정을 반영한다.

## 범위

- PDF 한 개를 업로드하고, 출력 형식(PPT/Word/Excel)을 라디오 버튼으로 선택해 변환·다운로드한다.
- **PPT**: 각 페이지를 이미지로 렌더링해 슬라이드 한 장에 하나씩 채운다. 텍스트는 편집 불가능(이미지로만 존재)하다.
- **Word**: 각 페이지의 텍스트를 추출해 문단으로 재구성한다. 표/이미지/다단 레이아웃 복원은 시도하지 않는다.
- **Excel**: 각 페이지의 텍스트를 줄 단위로 추출해 한 줄 = 한 행으로 A열에 그대로 넣는다. **열(칼럼) 분리는 시도하지 않는다** — 잘못된 칼럼 분리로 데이터가 뒤섞이는 것보다, 텍스트가 안전하게 한 줄씩 들어가는 쪽이 낫다는 결정.
- 텍스트 레이어가 없는 스캔 PDF에 대해 Word/Excel을 선택하면 변환을 중단하고 안내 문구를 표시한다(OCR 미지원).

## 목표가 아닌 것 (Out of Scope)

- **OCR** — 스캔 PDF(이미지로만 구성, 텍스트 레이어 없음)의 텍스트 인식은 지원하지 않는다. tesseract.js 등 OCR 엔진 도입은 번들 크기·속도 부담이 커서 명시적으로 제외했다(사용자 확인됨).
- **Excel 표(열) 자동 인식** — 텍스트 좌표를 분석해 열을 나누는 휴리스틱은 오탐 위험이 커서 채택하지 않는다(사용자 확인됨). 향후 필요성이 확인되면 별도 스펙으로 재검토한다.
- **Word 서식/레이아웃 복원** — 폰트, 표, 여러 단, 이미지 삽입 위치 등은 복원하지 않는다. 순수 텍스트를 문단 단위로만 재구성한다.
- **역방향 변환** (Word/Excel/PPT → PDF) — 이번 범위는 PDF를 출발점으로 하는 단방향 변환만 다룬다.
- **PDF 자체의 편집·병합·분할** — 기존 `pdf.html`의 다른 기능과 마찬가지로 범위 밖.
- **서버 API를 통한 변환** — 파일이 서버로 전송되지 않는다는 기존 원칙을 그대로 유지한다.

## 기술 스택 / 라이브러리

PDF 읽기(페이지 렌더링, 텍스트 추출)는 기존에 로드 중인 **pdf.js**를 그대로 재사용한다. 출력 파일 생성을 위해 새 라이브러리 3개를 CDN으로 추가한다 (기존 pdf.js/jsPDF와 동일하게 특정 버전에 고정, "latest" 금지):

- **pptxgenjs** — PPT(.pptx) 생성
- **docx** (docx.js) — Word(.docx) 생성, UMD 브라우저 빌드 사용 (`window.docx` 전역 노출)
- **SheetJS (xlsx)** — Excel(.xlsx) 생성

구현 시점에 각 라이브러리의 최신 안정 버전과 실제 SRI(integrity) 해시를 jsdelivr/cdnjs에서 직접 확인해 고정한다 (이 문서에는 정확한 버전 번호를 명시하지 않음 — 실제 배포 시점 값을 써야 하므로 구현 단계에서 확정).

세 라이브러리는 `pdf.html`에서만 로드한다. `index.html`(이미지 도구), `upscale.html`은 영향받지 않는다.

## 파일 구조

- `pdf.html` (수정) — "PDF → 문서 변환" 탭 추가(기존 "이미지→PDF", "PDF→이미지" 탭과 나란히, 독자적인 업로드 UI). pptxgenjs/docx/xlsx CDN 스크립트 태그 추가.
- `js/pdfConvertTools.js` (신규) — 순수 함수: 텍스트 아이템 → 문단/행 변환 로직, 스캔 PDF(텍스트 없음) 판별, 출력 파일명 생성. Node로 유닛테스트.
- `js/pdfConvertApp.js` (신규) — DOM 이벤트 와이어링, pdf.js 텍스트/페이지 추출 호출, pptxgenjs/docx/xlsx 호출 오케스트레이션. 기존 `upscaleApp.js` 패턴과 동일하게 UI 로직은 별도 테스트 대상으로 삼지 않는다.
- `tests/pdfConvertTools.test.js` (신규) — `js/pdfConvertTools.js` 유닛테스트 (기존 3개 test.js 파일과 동일 패턴).
- `pdf.html`은 `js/pdfConvertTools.js`도 함께 로드하며, 기존 `js/pdfTools.js`의 `getBaseFileName`, `isValidPdfFile`, `isValidFileSize`, `isValidPageCount`, `MAX_PDF_PAGES`, `MAX_FILE_SIZE` 등을 재사용한다(중복 구현 금지).

## 핵심 기능 및 데이터 흐름

### 공통 절차

1. 사용자가 새 탭에서 PDF 파일 하나를 선택한다. 기존 `isValidPdfFile`로 검증하고, `isValidFileSize`(20MB 이하)를 확인한다.
2. 출력 형식 라디오(PPT 기본 선택 / Word / Excel) 중 하나를 고른다.
3. "변환" 클릭 시 pdf.js로 문서를 열고 `numPages`를 `isValidPageCount`(≤300, 기존 `MAX_PDF_PAGES` 재사용)로 검사한다.
4. Word 또는 Excel이 선택된 경우, 전체 페이지의 텍스트를 먼저 추출해 텍스트가 실질적으로 존재하는지 판별한다(`pdfConvertTools.js`의 순수 함수로 판별 — 전체 페이지에서 추출한 텍스트를 trim한 총 길이가 임계값 이하이면 "스캔 PDF"로 간주). 스캔 PDF로 판별되면 변환을 중단하고 "이 PDF는 텍스트가 없는 스캔본으로 보입니다. PPT 변환을 이용해주세요." 안내를 표시한다. PPT는 이미지 기반이라 이 검사를 하지 않는다.
5. 변환 진행 중에는 기존 PDF→이미지 탭과 동일하게 "처리 중... (N/전체)" 진행 문구를 표시한다.
6. 완료 시 objectURL + `<a download>` 방식으로 다운로드를 제공한다(기존 도구들과 동일한 다운로드 방식). 파일명은 `<원본 베이스네임>.pptx` / `.docx` / `.xlsx` (기존 `getBaseFileName` 재사용).

### PPT 변환

1. 각 페이지를 off-screen canvas에 렌더링한다(`scale: 2`, 기존 PDF→이미지 탭의 렌더링 코드와 동일한 방식 재사용).
2. 캔버스를 PNG dataURL로 변환해 pptxgenjs 슬라이드에 페이지 크기에 맞춰 여백 없이 삽입한다(슬라이드 1장 = 페이지 1장).
3. 모든 페이지 처리 후 `pptx.writeFile()` 대신 blob을 받아(`pptx.write('blob')` 등 라이브러리 API에 맞춰) 기존 다운로드 방식으로 통일한다.

### Word 변환

1. 각 페이지에서 `page.getTextContent()`로 텍스트 아이템(문자열 + 위치 정보)을 얻는다.
2. 같은 페이지 안에서 텍스트 아이템들을 y좌표 기준으로 훑으며, y값이 이전 아이템과 유의미하게 달라지면 문단 구분으로 간주해 줄바꿈을 삽입한다(순수 함수로 `pdfConvertTools.js`에 구현, 유닛테스트 대상).
3. 재구성된 문단들을 docx의 `Paragraph` 배열로 만들고, 페이지 경계마다 페이지 나누기(`PageBreak`)를 삽입한다.
4. `Packer.toBlob()`으로 blob을 생성해 다운로드한다.

### Excel 변환

1. 각 페이지에서 `page.getTextContent()`로 텍스트 아이템을 얻는다.
2. y좌표가 같거나 유사한 아이템들을 한 줄로 그룹핑하고, 그 줄에 속한 텍스트를 x좌표 순서로 이어붙여 한 문자열로 만든다(열 분리 없음 — 범위 참조).
3. 한 줄 = 한 행으로 시트의 A열에 순서대로 채운다. 페이지가 바뀌는 지점에는 빈 행을 하나 삽입해 구분한다.
4. SheetJS `XLSX.utils.aoa_to_sheet` → `XLSX.write(..., {type: 'array'})`로 blob을 만들어 다운로드한다.

## 에러 처리

- 잘못된 파일 형식, 20MB 초과, 300페이지 초과: 기존 `pdf.html` 문구 패턴 재사용.
- 스캔 PDF + Word/Excel 선택: 위 "공통 절차 4" 안내 문구.
- CDN에서 pptxgenjs/docx/xlsx 로드 실패(오프라인 등): 실제 사용 시점에 해당 전역 객체 존재 여부를 확인해 "문서 변환 기능을 불러오지 못했습니다. 인터넷 연결을 확인해주세요." 안내(기존 pdf.js/jsPDF 로드 실패 처리와 동일한 패턴).
- 손상되었거나 읽을 수 없는 PDF: 기존과 동일하게 "PDF 파일을 읽을 수 없습니다" 표시.
- 모든 처리는 브라우저 내부에서만 이루어지며 파일은 서버로 전송되지 않는다 — 기존 원칙 유지.

## 네비게이션

- 새 페이지를 만들지 않고 기존 `pdf.html`에 탭만 추가하므로, `index.html`/`guide.html`/`sitemap.xml`의 상위 네비게이션 구조는 변경되지 않는다.
- `pdf.html`의 페이지 제목/description/FAQ(JSON-LD 포함)에 새 변환 기능을 반영할지는 구현 단계에서 SEO 관점으로 검토한다(범위 확정 사항은 아니며, 기존 FAQPage 구조에 자연스럽게 추가하는 정도로 처리).

## 테스트 방침

- `js/pdfConvertTools.js`의 순수 함수(텍스트 아이템 → 문단/행 변환, 스캔 여부 판별, 파일명 생성)는 `tests/pdfConvertTools.test.js`에서 Node 기반으로 유닛테스트한다.
- canvas 렌더링, pdf.js 텍스트 추출, pptxgenjs/docx/xlsx 연동 등 브라우저 전용 로직은 자동화 테스트 대상이 아니며, 실제 브라우저에서의 수동 검증에 무게를 둔다(기존 방침과 동일).
- 수동 검증 시 최소 다음 케이스를 확인한다: 텍스트 위주 PDF의 Word 변환, 표가 포함된 PDF의 Excel 변환(줄 단위로만 들어가는지), 스캔 PDF에서 Word/Excel 선택 시 안내 문구, 여러 페이지 PDF의 PPT 변환.

## 성공 기준

- 기존 "이미지→PDF", "PDF→이미지" 탭의 동작과 로딩 속도에 영향이 없다.
- 텍스트 기반 PDF를 업로드해 PPT/Word/Excel 세 형식 모두로 변환·다운로드할 수 있다.
- 스캔 PDF에 대해 Word/Excel을 선택하면 변환이 진행되지 않고 안내 문구가 표시된다(PPT는 정상 진행).
- 잘못된 파일, 크기/페이지 수 초과, 손상된 PDF 등 주요 실패 상황에서 한국어 에러 메시지가 표시된다.
